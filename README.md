# Mariam Juma Hamis – Virtual Assistant website (Terraform + GitHub Actions)

Everything that was first built by hand in the console, as code, in **eu-central-1**:

| Piece | Resource |
|---|---|
| Site files | Private S3 bucket (versioned, encrypted) + files from `website/` |
| CDN | CloudFront + Origin Access Control, HTTPS redirect, custom 404 (`error.html`) |
| Clean URLs | CloudFront Function (`cloudfront/clean-urls.js`): `/about` → `/about.html` |
| Reviews DB | DynamoDB `reviews` (key `id`, provisioned 5/5, auto scaling to 10, deletion protection) |
| Reviews API | Lambda `review-api` (Python 3.13) + least-privilege IAM role + log group |
| API access | Public Function URL, CORS limited to the CloudFront domain, both required permission statements |
| Wiring | `config.js` generated by Terraform so the page finds the new Function URL |
| CI/CD | `.github/workflows/terraform.yml` (OIDC, plan on PR, apply on `main` + cache invalidation) |

## One-time setup

1. **Bootstrap** (local, admin credentials):
   ```bash
   cd state-bootstrap
   cp terraform.tfvars.example terraform.tfvars   # set github_repo (and create_github_oidc_provider=false if the account already has the GitHub OIDC provider)
   terraform init
   terraform apply
   ```
   Note the outputs.
2. Local backend config: `cp backend.hcl.example backend.hcl` and paste the `backend_config` output into it (`terraform output -raw backend_config`). `backend.hcl` is git-ignored; nothing in `backend.tf` needs editing.
3. In GitHub: **Settings → Secrets and variables → Actions → Variables** → add:

   | Variable | Value |
   |---|---|
   | `AWS_ROLE_ARN` | `github_actions_role_arn` output |
   | `AWS_REGION` | e.g. `eu-central-1` (same as the bootstrap) |
   | `TF_STATE_BUCKET` | `state_bucket_name` output |
   | `TF_STATE_KEY` | `website/terraform.tfstate` (bootstrap `state_key`) |
   | `TERRAFORM_VERSION` | e.g. `~> 1.13` |
4. In GitHub: **Settings → Environments** → create `production` (bootstrap `github_environment`). Optionally add yourself as a required reviewer for a manual approval before every apply; GitHub only allows this on public repos or paid plans, so without it pushes to `main` apply straight away.
5. Commit and push to `main`. Commit the `.terraform.lock.hcl` files in the root and in `state-bootstrap/`.

All settings live in `variables.tf` (root and `state-bootstrap/`) with defaults; override them in `terraform.tfvars`.

## Deploy

- Open a PR → format check, validate, plan.
- Merge to `main` → plan, then apply (after approval, if the `production` environment has a required reviewer), then CloudFront invalidation `/*`.
- Edit anything in `website/` and push: the files are re-uploaded and the cache is cleared.
- Pushes that only touch `README.md` or `state-bootstrap/` don't trigger a run. To run it anyway: **Actions → Deploy website → Run workflow**, or `gh workflow run terraform.yml --ref main`.

Local run: `terraform init -backend-config=backend.hcl && terraform plan && terraform apply` (the site URL is in the `website_url` output).

## Things to know

- **Back up the bootstrap state:** `state-bootstrap/terraform.tfstate` (and `terraform.tfvars`) live only on the machine that ran the bootstrap and are git-ignored. Without them Terraform can no longer manage the state bucket and deploy role (the resources keep working).
- **"Not authorized to perform sts:AssumeRoleWithWebIdentity" in CI:** the repo probably uses GitHub's immutable OIDC subject claims. Run `gh api repos/<owner>/<repo>/actions/oidc/customization/sub --jq .sub_claim_prefix`, put the result in `github_subject_prefix` in `state-bootstrap/terraform.tfvars`, and re-apply the bootstrap.
- **Approving reviews:** new reviews are stored with `approved = false`. In DynamoDB → Explore items, edit the item and add/set `approved` as a **Boolean** `true`.
- **Old us-east-1 resources** from the console build are not touched. Delete them manually (and the old CloudFront distribution) once this stack works. The old Function URL in the HTML has been replaced with `/config.js`.
- **Deleting the stack:** set `dynamodb_deletion_protection = false`, apply, then destroy. Empty the site bucket first if needed (versioned).
- **Custom domain later:** needs an ACM certificate in **us-east-1** (CloudFront requirement) plus aliases in the distribution.
- The Google Form iframe and `hl=en` are unchanged in `website/index.html`.
